Loading Clean Data into the Silver Layer

How raw data collected from source systems gets validated, cleaned, and stored ready for business reporting.

Background

Two Layers, Two Purposes

Bronze Layer — Source Of Truth Data arrives here exactly as the source system sends it. No changes, no cleaning — just a safe copy of everything.
Silver Layer — Trusted Data Data here is cleaned, validated, and standardized. This is the version used by analysts and business reports.

This pipeline moves data from Bronze → Silver automatically, table by table.

Step 1 of 6

Reading the Instructions

Before doing anything, the pipeline reads a configuration file that tells it:

  • Which tables need to be processed
  • How to rename or transform each column (e.g. "CustomerID" → "customer_id")
  • What quality rules apply to each column (e.g. "this field must never be empty")

Think of it as the pipeline's recipe card — it knows what to do for each table without needing manual instructions every time.

Step 2 of 6

Reading from Bronze

The pipeline reads the latest data from the Bronze layer.

Smart loading It only picks up new or changed records since the last run — not the entire history every time. This keeps it fast and efficient.
Column mapping Columns are then renamed and reformatted to match the Silver layer's standard structure, using the rules from Step 1.
Step 3 of 6

Removing Duplicate Records

Source systems sometimes send the same record more than once. Before writing anything, the pipeline detects and removes duplicates.

Incoming records
→
Fingerprint each row
→
Keep only the latest version

Each row gets a unique "fingerprint" based on its content. If two rows have the same fingerprint, only the most recent one is kept.

Step 4 of 6

Data Quality Check

Every record is tested against quality rules before being saved.

✅

Valid records

Pass all checks and move on to be saved in Silver

🚫

Rejected records

Fail a check and are moved to a quarantine area for review

If all records in a batch are rejected, the pipeline stops safely and logs a warning — nothing incorrect is ever written to Silver.

Step 5 of 6

Writing to the Silver Layer

Valid records are saved into the Silver layer using one of two strategies:

Full Load Replaces the entire Silver table. Used for reference data or smaller tables that need a complete refresh.
Merge / Upsert New records are inserted. Changed records are updated. Unchanged records are left alone. This is the default for large, frequently updated tables.
Step 6 of 6

Audit Log — Always Written

At the end of every run — success or failure — the pipeline records a full summary:

  • 📥How many rows were read from Bronze
  • ✅How many were inserted or updated in Silver
  • 🚫How many were rejected by quality checks
  • ❌Any errors that occurred, with full detail for debugging

This means we always know exactly what happened — and can trace any issue back to the specific run and table.
