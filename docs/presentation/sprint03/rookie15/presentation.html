Medallion Architecture & Gold Layer Scope

Delta Merge Pattern (dim_quotation)

delta_table.alias("target").merge(
    source_df.alias("source"),
    "target.quotation_id = source.quotation_id"
).whenMatchedUpdate(
    condition="COALESCE(target.quotation_expiry_date,'')"
              " != COALESCE(source.quotation_expiry_date,'')",
    set={
        "quotation_expiry_date": "source.quotation_expiry_date",
        "updated_at": "current_timestamp()"
    }
).whenNotMatchedInsert(values={...}).execute()
Idempotent: if attributes haven't changed, the merge writes zero bytes. Safe to rerun on recovery.
SCD Type 2 — Historical Versioning

Track Changes, Preserve History

Four dimensions (dim_customer, dim_agent, dim_provider, dim_vehicle) use SCD2 with on-the-fly MD5 hashing — no hash column stored in the table.

Two-Phase Logic

Hash Generation (On-the-Fly)

Deduplicate source by business key (latest record wins). Compute MD5 of tracked columns for both incoming and active target rows.

Identify Actions

Join on business key. Hash differs → expire old + insert new version. Key missing → insert new. Hash matches → skip.

Expire via Merge

Set is_current = false, effective_to = event_time on matching active records.

Insert New Version

Append with is_current = true, effective_from = event_time, effective_to = 9999-12-31, new surrogate key.

PySpark Code — Hash & Detect

# On-the-fly MD5 hash of tracked columns
incoming = source_df.withColumn(
    "row_hash",
    F.md5(F.concat_ws("||",
        *[F.coalesce(F.col(c).cast("string"), F.lit(""))
          for c in tracked_cols]))
)

# Detect changed records
to_expire = joined.filter(
    F.col("tgt.customer_key").isNotNull() &
    (F.col("src.row_hash") != F.col("tgt.row_hash"))
)

Version Tracking Columns

  • effective_from — COALESCE(updated_at, created_at)
  • effective_to — 9999-12-31 23:59:59 (active row)
  • is_current — TRUE for active, FALSE for expired
  • Unknown row: effective_from = 1900-01-01
Fact Ingestion

Point-in-Time Key Lookups & Soft Deletes

Every fact table resolves dimension surrogate keys at the exact moment of the transaction. Late-arriving dimension changes never corrupt historical fact rows.

PIT Join Pattern (fact_quotation example)

# SCD2 Point-in-Time join
# quotation_at must fall inside the active version window
joined = source.join(
    dim_customer,
    (source.customer_id == dim_customer.customer_id) &
    (source.quotation_at >= dim_customer.effective_from) &
    (source.quotation_at <  dim_customer.effective_to),
    how="left"
)

# Default -1 if no match found
final_df = joined.withColumn(
    "customer_key",
    F.coalesce(F.col("dim_customer.customer_key"), F.lit(-1))
)

Soft Delete Handling

Records flagged is_deleted = true in Silver are never purged from Gold. Instead, measures are zeroed out and delete metadata is populated: deleted_at, delete_batch_id.

Audit & Control Flow

Run Modes & Recovery State Machine

A single-row control table (cfg.next_run_mode) drives pipeline behavior between runs. No manual intervention needed for common failures.

NEW

  • Default / post-success state
  • Increments batch_id
  • Fresh run from step 1

FAILED

  • Any table/layer errors
  • batch_id preserved
  • Sets next_run = RECOVERY

RECOVERY

  • Reuses failed batch_id
  • Skips SUCCESS tables
  • Resumes from failure point
Skip-Resume logic: any table with gold_status = 'SUCCESS' for the active batch_id is bypassed entirely — zero Spark compute wasted.

Data Quality

6-Check Automated Validation Suite

After every fact table ingestion, nb_gold_validate_reconciliation_dev runs 6 sequential checks. A single failure immediately aborts the pipeline and sets RECOVERY mode.

Check 1
Grain Uniqueness
Groups by logical grain columns for the active batch. Fails if any group count > 1 (duplicate keys).
Check 2
Foreign Key Integrity
Left joins fact against each dimension. Fails if any non-(-1) surrogate key has no match in dimension.
Check 3
Date Key Validity
Joins date keys against dim_date. Fails if any non-(-1) date key is unresolvable.
Check 4
Row Count Reconciliation
Gold row count must equal deduplicated Silver source count for the active batch. No dropped rows.
Check 5
Metric Reconciliation
Sum of financial columns in Gold vs Silver (soft-deletes zeroed out). Fails if variance > 0.01.
Check 6
Soft Delete Audit
Soft-deleted records (is_deleted = true) must have populated deleted_at and delete_batch_id.
Resilience Design

Idempotency & Zero-Data-Loss Recovery

Every layer is designed to be safely rerun without producing duplicates, corrupt keys, or wasted compute — critical for a shared Fabric capacity environment.

Guarantees per Layer

LayerIdempotency Mechanism
dim_dateExistence check before generation — bypassed if populated
SCD1 dimsMERGE match on BK; update only if attribute differs
SCD2 dimsMD5 hash compare; 0 writes if hash unchanged
Fact tablesMERGE on grain key; whenMatchedUpdate overwrites deterministically
ValidationReads current Gold state; no side effects on pass

Transient Error Retry

Transient DB/cluster errors trigger cfg.retry_policy (max retries + wait delay). Each attempt is logged in log.retry_log. Only non-retryable errors immediately abort.
